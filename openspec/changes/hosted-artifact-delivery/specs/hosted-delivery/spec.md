# Hosted artifact delivery requirements

### Requirement: bounded authenticated admission

A hosted admission layer SHALL authorize namespace access, enforce encoded and
decoded size/resource limits, and distinguish uploaded claims from observed
qualified generation provenance. Native key generation SHALL use an explicit
bounded worker with an exact official backend/parameter profile.

#### Scenario: large or unsupported input

- **WHEN** a request exceeds limits or lacks a qualified profile
- **THEN** admission refuses with a typed error without ready metadata or partial delivery.

### Requirement: complete immutable publication

Publication SHALL verify complete object inventories and atomically expose one
immutable set/view through conditional metadata publication and fenced leases.
Existing actual verifier identity SHALL survive eviction and regeneration.

#### Scenario: interrupted publication or stale worker

- **WHEN** object upload or metadata commit fails, or an expired worker completes late
- **THEN** readers see no partial set and the stale worker cannot replace the committed winner.

#### Scenario: regenerated bytes differ

- **WHEN** regeneration differs from a pinned output identity
- **THEN** the old URL/identity is retained and replacement is refused or published separately.

### Requirement: qualified FetchZkConfigProvider views

A provider view SHALL preserve exact binary IR/prover/verifier bytes and the
compiler integrity/runtime metadata required by its pinned official consumer.
A Forge descriptor SHALL NOT substitute for compiler provenance or disable checks.

#### Scenario: exact consumer retrieval

- **WHEN** an authorized pinned browser or Node provider retrieves a complete immutable view
- **THEN** its integrity checks and real proof verification pass with original assertions running.

### Requirement: transparent representation compression

Compression SHALL preserve canonical decoded-byte identities, maintain separate
encoded-byte metadata, bound decompression and negotiate coherent HTTP encoding,
ETag, Vary, HEAD and Range semantics.

#### Scenario: encoded response and range request

- **WHEN** a client requests gzip/Brotli or an identity byte range
- **THEN** the decoded artifact matches its canonical digest and range offsets/validators
  refer to the actual selected representation, without mixed-encoding cached responses.

### Requirement: private cache isolation

Private delivery SHALL authorize before serving CDN hits and prevent namespace,
credential and response leakage. Authorization failures SHALL NOT become success hits.

#### Scenario: unauthorized warm CDN lookup

- **WHEN** another namespace/user requests an already cached private artifact
- **THEN** access is denied regardless of content deduplication or CDN warmth.

### Requirement: measured cost and local qualification

Any hosting recommendation SHALL state date, region, traffic/storage/CPU/metadata
assumptions, free-tier eligibility and omitted costs, distinguishing measurements
from projections. Deployment SHALL require separate owner authorization.

#### Scenario: compression savings claim

- **WHEN** a proposal claims lower storage or delivery cost from compression
- **THEN** it cites measured consumer artifact sizes and accounts for retained raw variants,
  compression/decode compute, CDN transfer policy and request charges.
