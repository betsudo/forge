# Design

The SDK's public save API does not expose a pre-reservation size policy. Audit its exact locked implementation and install one process-local guarded internal size-observation hook. The SDK itself creates and uploads the same archive. Refuse unknown code/version, repeated size callbacks or denied budget before CreateCacheEntry. Validate exact default-off/trusted manual branch, official prepare-save result/current primary key/ID/partition and fixed snapshot path. At the measured-archive seam obtain complete service cache inventory and active/queued workflow inventory. Refuse unknown writers/API/inventory/size, over decimal 10 GB or retained-generation budget. A human-approved exclusive operational window is an explicit assumption; the tool audits current jobs but does not claim atomic control over independent future writers.

Tests run the actual SDK with fake service/client boundaries and must prove denial causes zero reservation/upload. No alternative archive, ratio estimate, service protocol or runtime payload change. Npm lock and source-byte contract pins guard this intentionally internal seam. This is a narrow CI-only tool, not a general cache manager; no deletes or automatic eviction.
