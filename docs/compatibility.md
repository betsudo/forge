# Consumer compatibility and artifact identity

Forge exposes the same path-free `descriptor` object in CLI import/inspect/
prepare/ensure/resolve/export and HTTP registration/inspection/materialization.
Exports retain their original immutable `manifest.json` and add `descriptor.json`.
The descriptor is additive; existing Record/SQLite schema and identity transcripts
are unchanged. A different implementation build still creates its conservative
new recipe partition; existing historical identities are never rewritten.

Descriptor v1 fields:

| Field | Meaning |
| --- | --- |
| schema | Descriptor version 1, independent of outer response versions. |
| input_format, input_version | Actual source dialect and major/minor from verified exact source JSON. |
| record.source | Source kind, digest and byte length. |
| record.bundle_id, name | Source registration identity/name; names can share generated outputs. |
| materialized | Generation facts exist; this does not mean all stored objects are currently available. Check outer ready and verify actual downloaded bytes. |
| record.profile, ledger_revision | Exact official backend premises. |
| serialization | Actual binary IR/prover/verifier tags. V2 IR is `ir-source[v2]`; v3 is `ir-source[v3-generic]`. Keys use `prover-key[v7](IR_TAG)` and `verifier-key[v6]`. |
| record.build_fingerprint, worker | Conservative implementation premise; materialized v3 requires the exact worker profile/revision/build/executable SHA-256. |
| record.k, parameter_digest | Size and SHA-256 of actual upstream-verified parameter bytes. |
| keygen_recipe | `library-keygen/default-options/no-rng`; no alternative options are implicitly supported. |
| record.derivation_id, artifact_set_id, artifacts | Recipe and actual output inventory identities, with each kind/digest/byte length. |

Registration lacks generation facts and has null serialization/recipe. Timing is
excluded (`record.generation_ms` is null); local paths and HTTP URLs stay outside
the descriptor. Consumers accept only supported versions. Rust consumers can use
`descriptor::ArtifactDescriptor::decode`: it rejects duplicate, missing required,
unknown nested and inconsistent identity/tag/recipe fields. JSON Schema is in the
OpenAPI document, but does not replace cross-field and digest verification.

## Consumer acceptance and fallback

A Compact adapter or other consumer must have an independent qualified policy:
backend revision/profile, source dialect/serialization, root build and worker
allowlists, parameters/k and generation options. Compare all descriptor premises
with that policy, the exact current source bytes, and the actual artifact inventory.
Do not ask the candidate executable to qualify itself. A matched descriptor is not
publisher authentication. Do not change a consumer's old build allowlist based only
on a matching version string. Compact is unchanged in this increment.

Conceptual shared acceptance flow for either transport:

```text
CLI:  response.descriptor + response.export.files
HTTP: response.descriptor + response.artifacts[].url/sha256/bytes

require outer availability and descriptor schema == 1
strict-decode and validate all identity relationships
compare source bytes and every qualified premise with independent policy
read/download each artifact, check kind, size and SHA-256
supply the accepted artifacts to the existing ZK config provider
run actual proofs, verification, assertions and negative controls
```

Semantic compatibility is an independently tested consumer/backend agreement.
Exact derivation reproducibility also requires equal recipe premises. Output-set
identity describes actual generated bytes; different recipes can produce equal
outputs. These concepts are not interchangeable.

Application failures use typed kinds; diagnostic substrings never choose fallback.
CLI returns nonzero and JSON with code/message/retryable/availability_fallback;
message is safe code text and full diagnostics remain on stderr. Clap argument
errors remain human-readable stderr exceptions. HTTP returns the same safe fields
without source material, paths, tokens or upstream exception text.

| Code | HTTP | Availability fallback |
| --- | --- | --- |
| parameters_unavailable | 503 | Permitted by consumer policy; offline missing material. |
| invalid_parameters | 422 | Never; present bytes failed official verification. |
| profile_format_mismatch, worker_profile_mismatch | 409 | Never. |
| unsupported_zkir_version, invalid_input | 400 | Never. |
| integrity_error, artifact_identity_changed | 409 | Never. |
| not_found, artifacts_unavailable | 404 | Permitted by consumer policy. |
| unauthorized | 401 | Never. |
| busy and HTTP admission subcodes | 429 | Retryable, with Retry-After. |
| internal_error | 500 | Refuse; insufficient evidence for availability fallback. |

Unknown errors fail closed. A transport connectivity failure may use the consumer's
original fresh generation path under its own policy; it does not turn a corrupt or
incompatible response into a miss. Upstream fetch failures that conflate network
and digest errors are conservatively refused, not guessed from prose. Parameter
retrieval remains offline unless explicitly enabled. Local unreadability is not
proof that material is simply unavailable.

## Persistence and validation

Old export manifests stay byte-for-byte unchanged. A missing descriptor sidecar is
added atomically only after source/CAS/export verification. A conflicting sidecar
is refused, never rewritten. Snapshots accept absent legacy sidecars and verify
present sidecars against their historical export record/source. Current snapshot
producer partitioning remains conservative; no old-producer bypass or silent
snapshot migration is introduced.

Run `scripts/check-compatibility.py --binary target/debug/midnight-zkir-forge`
through `./bootstrap.sh --` for both-profile descriptor parity, legacy export and
CLI/HTTP parameter controls. It needs verified local k4 parameters. Rust descriptor
unit/ignored real tests cover strict decoding and independent premise changes.
Existing real HTTP/snapshot/recovery suites continue to prove warm artifacts and
reject invalid statements/corrupt proofs. Process cold/warm timings and per-job
stats deltas are reported separately; tiny fixtures are not a general speedup claim.

Rust consumers use `ArtifactDescriptor::decode(bytes)`; unchecked public Serde
deserialization is intentionally unavailable. Validation does not establish trust
in a producer: enforce an independently qualified consumer policy as well.
