# Minimal hosted key delivery recommendation — 2026-10-16

Status: proposed architecture, not a deployment or accepted ADR. Supports the
owner's first priority (compiler/provider key fetching); local CLI reuse remains
independent and CI speedup is evaluated separately. Tracking:
[betsudo/forge #8](https://github.com/betsudo/forge/issues/8).

## Recommended first candidate

| Responsibility | Component |
| --- | --- |
| Small authenticated Rust HTTP API | Cloudflare Worker compiled to Wasm using workers-rs. |
| Metadata when a mutable catalog is required | D1: managed serverless SQL with SQLite semantics. |
| Binary IR, prover/verifier keys and immutable manifests | R2 object storage, not database blobs. |
| Delivery | CDN/custom-domain routes with deliberate cache rules for artifact types; private access must be checked before cache lookup. |
| Key generation | Existing qualified native Forge CLI/CI workers initially. Publish complete verified sets, then make a provider view ready. |

This is a recommendation based on the small read-heavy design and transfer-cost
model, not a proof that it is globally cheapest. Rust/Wasm is not the same runtime
as native Forge. Do not assume the native cryptographic library graph can execute
in a Worker. Cloudflare documents [Rust Workers and Wasm plumbing](https://developers.cloudflare.com/workers/languages/rust/)
and [D1's SQLite SQL semantics](https://developers.cloudflare.com/d1/).

For the smallest read-only pilot, immutable manifests and known object URLs may
remove the need for D1 entirely. Add the catalog only for mutable lookup,
publication state or authorization data. Do not put the existing local SQLite
file on an object bucket and treat it as a concurrent database.

Native Rust function alternative: **AWS Lambda + DynamoDB + S3 + CloudFront**.
Choose this if native Rust execution or existing AWS operations matter more than
one integrated low-egress storage stack. AWS documents a [Rust runtime client
with an OS-only Lambda runtime](https://docs.aws.amazon.com/lambda/latest/dg/lambda-rust.html).
S3/CloudFront/DynamoDB costs must be modeled separately; neither design moves
expensive keygen into a synchronous request by default.

## Current cost facts and limits

R2 Standard lists **$0.015/GB-month**, with Class A **$4.50/million**, Class B
**$0.36/million**, and free Internet egress. Free allowances and billing-unit
rounding affect the actual bill. This is storage/operations pricing, not the
complete service cost. [Official R2 pricing](https://developers.cloudflare.com/r2/pricing/).

Workers Paid has a **$5 monthly base**; API requests/CPU, metadata, domains,
logging, backups, generation and any paid access controls must be accounted for
separately. Free plans may suffice for qualification within their limits; no
subscription is selected by this plan. [Official Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/)
and [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/).

R2 custom-domain delivery can use Cloudflare Cache, but caching is not automatic
for every extension and object size. Validate the largest actual prover key and
cache policy. The r2.dev endpoint is intended for development, not production
CDN service. Private keys must not have an unprotected public-bucket bypass.
[Official bucket/custom-domain guidance](https://developers.cloudflare.com/r2/buckets/public-buckets/).

Generate/verify canonical original bytes first; measure gzip/Brotli and retain
compressed variants only when useful. Hash original bytes for artifact identity;
encoded bytes have separate representation hashes/sizes. Test actual Fetch
provider decoding, Content-Encoding/Vary/ETags and consistent range behavior.
Do not promise large compression savings without measurements.

## Consumer-facing contract

The compiler integration opt-in is proposed, not a shipped flag. It should select
verified reuse and preserve normal compiler manifests/integrity metadata. The
same qualified provider layout should work with NodeZkConfigProvider locally and
FetchZkConfigProvider over HTTP(S), as described in the [official Midnight provider
guide](https://docs.midnight.network/guides/deploy-and-operate). Pin and test the
actual SDK versions before claiming compatibility.

Start with trusted complete-set publishing and immutable provider URLs. Raw ZKIR
admission, asynchronous hosted keygen, tenant scheduling and Proof Relay remain
later work. No account/credential/DNS/infra mutation, upload or deployment is part
of this research refresh. See the [original detailed research](../research/hosting-costs.md)
for wider vendor comparisons and explicitly illustrative cost scenarios.
